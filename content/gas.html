트랜잭션의 구조

{
  "from":     "0x71C7...976F",   // 서명에서 복원됨 (실제로 필드에 없음)
  "to":       "0xA0b8...eB48",   // 받는 주소 (컨트랙트면 함수 호출)
  "value":    "1000000000000000000", // 1 ETH를 wei로 (10^18)
  "data":     "0xa9059cbb000000...",  // 호출할 함수 + 인자 (ABI 인코딩)
  "nonce":    42,               // 이 계정의 몇 번째 트랜잭션인가 (재전송 공격 방지)
  "gasLimit": 21000,            // 최대로 쓸 가스량
  "maxFeePerGas": "2000000000",        // 가스당 지불 상한 (2 gwei)
  "maxPriorityFeePerGas": "100000000", // 검증자 팁 (0.1 gwei)
  "chainId":  1,                // 이더리움 메인넷 (다른 체인 재사용 방지)
  "v","r","s": // ECDSA 서명 3요소
}

단위 체계

단위wei 기준쓰임
wei1최소 단위. 모든 코드 내부 계산은 wei로. 정수만 사용(부동소수점 없음)
gwei10⁹가스 가격 표기용
ether10¹⁸사람이 읽는 단위

⚠️ 프론트엔드가 가장 많이 실수하는 지점

10¹⁸은 JavaScript Number의 안전 정수 범위(2⁵³ ≈ 9×10¹⁵)를 초과합니다. 반드시 BigInt를 쓰세요. viem은 모든 금액을 bigint로 다루고 parseEther() / formatEther()를 제공합니다. Number(balance)로 캐스팅하는 순간 사용자 잔고가 조용히 틀려집니다.

가스: 왜 존재하는가

모든 EVM 명령어에는 정해진 가스 비용이 있습니다. 덧셈 3, 저장소 쓰기 20,000, 저장소 읽기 2,100 하는 식입니다. 저장이 연산보다 수천 배 비싼 것이 EVM 경제학의 핵심입니다.

수수료 계산 (EIP-1559 이후):

총 수수료 = gasUsed × (baseFeePerGas + priorityFee)
             ↑ 실제 사용   ↑ 소각됨(burn)    ↑ 검증자에게

baseFee는 프로토콜이 블록 혼잡도에 따라 자동 조절하며 소각됩니다(EIP-1559, 2021). 즉 네트워크를 쓸수록 ETH 공급이 줄어듭니다.

2026년에 달라진 것: "이더리움은 비싸다"는 이제 낡은 전제

2021~2023년의 기억으로 이더리움을 판단하면 안 됩니다. 세 번의 업그레이드가 비용 구조를 바꿨습니다.

업그레이드시점핵심 변화
The Merge2022.09PoW → PoS 전환. 전력 소비 ~99.95% 감소
Dencun2024.03EIP-4844 "블롭" 도입. 롤업에 별도의 저렴한 데이터 차선 제공 → L2 수수료 10~100배 하락
Pectra2025.05EIP-7702 (EOA에 스마트 계정 기능), 블롭 처리량 증가
Fusaka2025.12PeerDAS(블롭 샘플링), 가스 리밋 60M 표준화, secp256r1 네이티브 지원(패스키 서명 저렴해짐)
Glamsterdam 예정2026 하반기블록 단위 액세스 리스트(BAL) + ePBS. 가스 리밋을 200M 수준까지 올릴 길을 염

결과적으로 2026년 5월 기준 이더리움 메인넷 표준 가스는 약 0.15 gwei, 4월 일평균 약 0.5 gwei였고, 단순 ETH 전송은 1센트 미만입니다. 동시에 전체 트랜잭션의 약 95%가 롤업(L2)에서 처리됩니다.
